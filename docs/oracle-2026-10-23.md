# Oracle 2026.10.23 conformance

PR [122](https://github.com/unbraind/pm-rust/pull/122) updates the locked oracle
from 2026.10.21 to 2026.10.23. The original
[Ubuntu job](https://github.com/unbraind/pm-rust/actions/runs/40269872574/job/121400153960)
reported 21 passing and 11 failing orientation differential tests.

The [upstream release notes](https://github.com/unbraind/pm-cli/blob/v2026.10.23/CHANGELOG.md)
document both relevant changes under 2026.10.22: GH-1534 retains root relationship
evidence before optional context detail; GH-1535 reports test health over the
matching population. The 2026.10.23 entries add no relationship behavior changes.
The shipped relationship kernel and upstream integration regressions confirm the
ordering, edge reservation, cursor version, and omission rules below.

Every original failure is class **(a), intentional upstream change**:

| Failing test | Captured difference and required behavior |
| --- | --- |
| `context_blocked_fallback_deep_matches_oracle` | Add `tests.scope: matching_active_items` and `tests.total_items: 0` for blocked-only work. |
| `context_completion_rounding_matches_oracle` | Add the complete active denominator, 172, despite focus limit 1; preserve completion rounding. |
| `context_matches_oracle` | Add test-health scope and denominator, including empty populations. |
| `context_sections_match_oracle` | Add scope and denominator, 4; summarize test health before focus packing and paging. |
| `padded_inverse_blockers_match_oracle` | Add scope and active denominator, 1; preserve inverse blocker normalization. |
| `real_copy_harness_accepts_matching_packet_refusals` | Recalculate JSON floor advice after root evidence packing and producer-bounds disclosures. |
| `relationship_external_namespaces_match_oracle` | Place prerequisite endpoints ahead of optional related external nodes, preserving distinct namespaces. |
| `relationship_large_edge_limit_finishes_at_budget_floor` | Charge the producer-bounds receipt during recovery; the captured TOON feasible/minimum floor changes from 331 to 348. |
| `relationship_packet_refusals_match_oracle` | Preserve the query while recomputing rendered recovery advice; the captured TOON feasible budget changes from 392 to 448. |
| `relationship_packets_match_oracle` | Prioritize direct prerequisite/ancestor endpoints; reserve direct edge costs; emit root-incident edges first; skip unaffordable edges; version cursor ordering; disclose producer truncation independently of full projection. |
| `relationship_reference_limits_match_oracle` | Include bounds disclosures in rendered recovery; the captured edge-limit-1 feasible budget changes from 377 to 434. |

The captured budget values describe those fixtures, rather than constants to
embed in the implementation. Recovery must probe the preserved query and count
the actual delivered JSON or TOON bytes. Exact stdout, stderr and exit-status
comparisons remain in place for all existing differential tests.

No class (b) regression or undocumented contract change was identified among
these eleven orientation failures. The additional crash-gate blocker below is
classified separately.

A direct probe of both published kernels also confirms the ordering change.
For edges `a-child -> root (parent)` and `root -> z-blocker (blocked_by)`,
with `nodeLimit: 1`, 2026.10.21 returns `a-child` and its parent edge;
2026.10.23 returns `z-blocker` and its blocking edge. Both report one omitted
node. The focused native tests reproduce the new ordering and continuation.

## Additional upstream blocker: frozen-clock restart

Class **(b), upstream regression or undocumented contract change**: after killing
a published update at its first per-task `rename`, a published restart comment
returns successfully with 2026.10.21 but exceeds the unchanged 15-second external
deadline with 2026.10.23. Both use the existing crash harness's frozen `Date`
preload and live elapsed time. The retained item lock belongs to a dead process.
This is evidence about that deterministic fixture; it does not establish a hang
under an ordinary advancing wall clock.

An independent probe of both installed packages measured 2026.10.21 returning
exit 0 in 559 ms, and 2026.10.23 reaching the 15-second deadline. The project
oracle remains pinned to 2026.10.23. No native recovery behavior or harness
deadline is changed to imitate or accept the timeout.

Minimal Linux reproduction from the package root, with the locked oracle
installed (use a separate 2026.10.21 installation for the control):

```bash
repo=$PWD
oracle=$repo/tests/oracle/node_modules/@unbrained/pm-cli
work=$(mktemp -d)
cd "$work"
pm_oracle=(env HOME="$work/isolated-home" UV_THREADPOOL_SIZE=1
  NODE_DISABLE_COMPILE_CACHE=1 PM_SENTRY_DISABLED=1
  PM_TELEMETRY_SOURCE_CONTEXT=test DO_NOT_TRACK=1 LC_ALL=C TZ=UTC
  node --import "$repo/scripts/crash-clock.mts" "$oracle/dist/cli.js")
"${pm_oracle[@]}" init --defaults --prefix crash- --agent-guidance skip --json --no-extensions
"${pm_oracle[@]}" create Task "Synthetic crash probe" --id crash-probe \
  --description "Acknowledged synthetic write" --create-mode progressive \
  --author conformance-agent --json --no-extensions
strace -f --kill-on-exit -qq -o kill.trace -e trace=rename \
  -e inject=rename:signal=SIGKILL:when=1 -- "${pm_oracle[@]}" \
  update crash-probe --description "Interrupted synthetic write" \
  --author conformance-agent --json --no-extensions
timeout --signal=KILL 15s "${pm_oracle[@]}" comment crash-probe \
  "Restart synthetic sentinel" --author conformance-agent --json --no-extensions
```

Expected: the preserved restart command recovers the dead writer and returns
exit 0, as observed with 2026.10.21. Actual with 2026.10.23: no response before
the external deadline. The original five crashing-harness failures all report
this timeout rather than an accepted recovery result. Targeted upstream issue
searches found no matching frozen-clock/rename restart report; the orchestrator
should confirm deduplication and file this reproduction upstream.
