## Coverage resolution

Pair-preserving compaction cannot manufacture a lone surrogate. The unreachable
top-level CLI error handler and redundant post-compaction TOON validation were
removed. `compact_budget` now returns its result directly because that pass has
no remaining fallible operation.

The lossless JSON codec contract remains supported. A documented
`ListOutput::with_json_overrides` constructor allows callers to retain raw JSON
overrides with a Unicode-safe view. Serialization validates surviving raw
fragments; TOON refuses surviving overrides. Tests cover this refusal through
the binary's output writer and the library, including short escape fragments
that must return an error without panicking. Brief rows use the normal
extra-metadata lookup for the remaining validated sort key (`deadline`),
removing an unreachable unknown-sort-only arm. Explicit producer limits share
one parser for both truncation modes. No coverage thresholds or exclusions change.

Invalid explicit producer limits are tested both on the first page and with an
offset. Offset requests bypass the first-page optimization and exercise the
pagination parser's own error propagation under `--no-truncate`.

### PR 100 nullable sort review

Thread `PRRT_kwDOTwgMRs6uY9EN` found that `--for triage --brief --sort parent`
or `--sort deadline` omitted an absent sort key. Intent selection reads full
metadata before projecting brief rows; the projection now explicitly inserts
`null`, matching ordinary brief rows and the pinned oracle.

`nullable_sort_values_survive_intent_brief_projection` compares both SDK paths
for every supported sort key and alias in ascending and descending order. Its

`nullable_intent_brief_sort_values_match_both_wire_encodings` compares exact
JSON and TOON output against the pinned oracle for both nullable keys and both
orders, and checks JSON key presence and populated values. TOON retains its
normal omission of null scalar fields. The full PR diff was inspected for the
same defect classes; no additional instance was found. The latest CodeRabbit
review contained no outside-diff findings.

With both regressions retained, reverting only `project_brief_rows` compiles
successfully and makes the SDK regression fail its row-equality assertion on
`parent asc`. The CLI regression also compiles and fails its exact wire
comparison where the native row omits `parent: null`. Both commands exit 101;
restoring the fixed function passes both linked tests. The commands are
`cargo +1.90.0 test --locked --lib nullable_sort_values_survive_intent_brief_projection`
and
`cargo +1.90.0 test --locked --test pagination_differential nullable_intent_brief_sort_values_match_both_wire_encodings`.
